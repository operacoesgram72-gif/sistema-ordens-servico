Melhorias e Correções do Sistema

Realize todas as alterações abaixo mantendo a estabilidade do sistema. Não remova funcionalidades existentes que já estejam funcionando. Antes de alterar qualquer componente, verifique dependências para evitar regressões.

Fluxo de Ordem de Serviço (OS)
No menu Funcionários, ao clicar em Registrar Nova OS, não deve abrir diretamente o formulário.

Deve aparecer uma tela com duas opções:

Abrir OS
Fechar OS
Abrir OS
Deve abrir exatamente o formulário atual de criação de Ordem de Serviço.
Manter todos os campos e funcionalidades existentes.
Fechar OS
Deve abrir a lista de Ordens de Serviço.
Nesta tela, somente a coluna "Status" poderá ser alterada, permitindo fechar a OS.
Todos os demais campos devem permanecer bloqueados (somente leitura).
O usuário não poderá editar nenhuma outra informação da Ordem de Serviço.

Separação de Dados por Estado (UF)
Corrigir o armazenamento dos dados por Estado.

Atualmente, ao selecionar um Estado (ex.: AC), são exibidos registros pertencentes a outro Estado (ex.: AM).

Isso não pode acontecer.

Cada UF deve possuir:

Banco de dados independente (lógico)
Registros independentes
Painel independente
Relatórios independentes
Fornecedores independentes
Ordens de Serviço independentes
Funcionários independentes
Materiais independentes

Ou seja:

Os dados cadastrados em uma UF nunca poderão aparecer em outra.

Toda consulta deve considerar obrigatoriamente a UF atualmente selecionada.

Requisitos Gerais

Durante toda a implementação:

Não remover funcionalidades existentes.
Não alterar layouts que já estejam funcionando sem necessidade.
Não quebrar integrações existentes.
Garantir compatibilidade com todo o sistema.
Validar todas as alterações antes de finalizar.

Ao concluir:

Verificar se todas as telas continuam funcionando.
Verificar navegação.
Verificar exportações.
Verificar filtros.
Verificar cadastro, edição e consulta.
Verificar persistência dos dados.
Caso os créditos do Replit terminem durante a execução

Se os créditos se esgotarem antes da conclusão:

Não deixar nenhuma funcionalidade parcialmente implementada.
Não deixar código incompleto.
Não deixar componentes quebrados.
Finalizar de forma segura, preservando 100% das funcionalidades existentes.
Todas as alterações já iniciadas devem permanecer funcionais e consistentes.
Priorizar a integridade do sistema em vez de deixar implementações incompletas.
